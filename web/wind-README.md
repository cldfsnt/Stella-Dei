# Staged main-game wind integration (not live)

`wind-origin.js`, `wind-storage.js`, `wind-prepare.py` implement a candidate targeting agreed native APIs, not a new hosted path. Released root and Wetlands controllers/loaders are not wired or modified. The preparer only accepts isolated `wind-dispersal/web`; it copies main UI assets, adds controls inside existing World/Plant groups, and installs candidate storage. It does not copy native code, build or deploy.

Native contract: `stella_wind_snapshot` yields status unavailable/classic/wind, world_serial, enabled, writer_version0/7/11, law0/1 and selected cell. `stella_wind_new(expected_world)` returns1/-1/-2stale/-3busy, creates explicit new world only. `stella_seed_pioneer(expected_world,cell)` returns1/0refused/-1/-2/-3. Ordinary existing Seed unchanged. `stella_save_expected(world,writer)` must perform its native recheck AFTER event-loop pump, immediately before serialization; -6 means mismatch. No fallback to unguarded save when wind policy is active.

The staged UI checks storage busy, Advance lock, current world/cell, confirmation cancellation and returned law state. It never autosaves, autoseeds or silently converts existing lineages. Allocation is not a measured launch count or guarantee of establishment. Actual public native workflow remains a separate release gate. Selected-trait field display awaits exact allocation-array schema; no speculative receipt is shown.

Backup is chosen from authoritative current writer, not target-schema option alone: classic7 writes never freeze a pre-v11 backup. Before writer11 replaces a known prior1..7 save, exact current bytes are durably preserved at `/saves/world.pre-v11.json`. If that immutable canonical file contains different prior bytes, use `/saves/world.pre-v11.sha256-<SHA256-of-exact-bytes>.json`, verifying any existing path byte-for-byte. First backup/pre-v7 remain intact. No cleanup or automatic restore. Missing secure SHA256, unknown/opaque version, corrupt/hash-path mismatch, quota/read/write failures and world/writer/prior-byte changes abort before serialization. Existing11 files and no prior file require no legacy copy. `storageOperation` spans hashing, backup sync, native save and final sync. A native -6 cannot silently save another world. Known prior bytes are retained only for the operation, not persisted in a hidden cache.

Tests: `node --test web/tests/wind-origin.test.cjs`; `node web/tests/wind-storage.test.cjs`; full existing suite remains applicable. First preparer run stopped on exact World-section anchor because source has `hidden`; corrected unique h3 anchor before candidate output. No published artifacts affected.
