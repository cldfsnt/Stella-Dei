# v30 fire-control gate: bounded proposal, not production

Current source inspected: stella-source-v16 after v30 film integration. No source changes or deployment.

## Why the old combustion planner cannot simply be connected

Origin tracks carbon biomass/support/detritus and global atmospheric O₂/CO₂, but schema6 has no tissue or detrital moisture. External water zero is not measured dry fuel. Existing structure is architecture/desiccation investment, not bark/fire resistance. Passing moisture_known=true and body_water=0 would invent missing state. Thin-film photosynthesis does not fix this.

Sandbox tracks vegetation cover and inherited temperature optimum, not carbon mass. Translating cover into combustion carbon would create a new undocumented mass model. Its rabbits have real food/energy/health simulation but no fire-specific escape or injury mechanism.

The pure foundation at ../stella-fire-lab remains useful but unconnected. It must not show flames for rejected or unknown-moisture requests.

## Recommended first observable control: Sandbox Scorch

This is an explicit destructive god intervention, NOT natural wildfire or carbon-conserving combustion. UI must use Scorch, not Fire. Origin declines with an explanation; wet Sandbox patches decline without heat/effect.

Proposed one-shot selected-patch transaction:
- Verify expected selection, Sandbox mode, bounds, finite temperature/cover/water, positive finite current patch heat capacity, positive cover, zero external surface water.
- Remove 75% of actual dimensionless cover (read back actual f32 difference), retain the remainder and inherited optimum/generation unchanged.
- Add existing heat-impulse behavior: up to40K bounded at500K. Receipt reports actual removed cover fraction and externally supplied J, NOT burned carbon/O₂ or combustion heat.
- Compute all proposed updates before any mutation; invalid/stale/wet requests leave complete state unchanged. Neighbors untouched.
- No direct rabbit kill, guaranteed recovery, seedbank or fire-resistant form. Existing thermal fitness and reduced food subsequently affect the real plant/rabbit model. Equal cover/temperature inputs get equal intervention regardless of visual morphology.
- Brief localized charcoal/heat indicator only after accepted transaction; no flame on water. Clear receipt says cover removed and heat added, ecology responds over time.

## Acceptance gates before offering it

1. Atomic invalid/stale/wet/zero-fuel rejection; finite bounded heat; exact cover readback; no neighbor or trait mutation.
2. Repeated actions cannot increase cover, exceed500K or create plants. Existing growth can recover surviving cover only under ordinary modeled conditions; zero cover remains zero absent normal colonization.
3. Actual Sandbox rabbit scenario compares unchanged initial state against Scorch, recording cover, food consumption, energy/health and deaths. Do not label flight/avoidance if not implemented.
4. Old schema6 roundtrip, immediate paused save after action and exact restore; no schema extension.
5. Actual UI tap/receipt/effect agreement and no effect after rejection; native and browser evidence labeled separately.

A real Origin fire control should wait for coherent fuel hydration and numerical gas transaction validation. Do not resolve that by silently using an unmeasured zero or inventing trait-specific immunity.
