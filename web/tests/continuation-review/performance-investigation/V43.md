# v43 acceptance: sparse traversal and local renderer context

Production change: keep the original full growth scan, build a transient ordered
activity bitset during it, and visit active cells for movement and births.
Future-index destinations are marked immediately, including in the same word;
phase cursors reset. No arithmetic, per-cell random sequence, resources, model
parameters, grid detail, requested pace, graphics or save schema changed. Index
allocation failure uses the original complete linear scans. Memory is one bit
per cell plus word padding, freed using the same allocator within each tick.

Acceptance:
- Three production helper tests passed, including word boundaries, future/lower
  writes and allocation-failure fallback. Independent read-only review found no
  release blockers.
- Seven actual scheduler 180-day comparisons (six multigeneration habitat/seed
  runs, one forcing OOM) reproduce every cohort, RNG, gas, statistics and feedback
  field each tick. Fixtures exercise thousands of births and real relocations.
- Real saved 40,962- and 163,842-cell coupled replays reproduce exact full JSON
  saves in all arms and restore the original world exactly.
- Deliberately dense 40,962-cell stress case: every patch occupied, 40,970 cohorts,
  40,952 real paid seeds after explicitly prescribed wet/303K conditions. This
  is a stress fixture, not natural ecological evidence. Four full-world hashes
  are identical. One pair improved, another regressed 1.24%; no major regression
  demonstrated, and no universal speedup inferred.
- Clean sparse 163,842-cell coupled CPU pairs: 2542→2078 ms and 2542→2019 ms for
  60 ticks (18.3% and20.6% lower). These are native CPU proxy results, not browser
  frame rates or Todd's laptop measurement. Small40k timings are noisy, so **no
  reliable Android or40k speedup claim**. Graphics and climate still cost time.
-13 JS/shell tests and the full WASM build passed. Optional renderer context is
  read only on successful explicit10-second measurement start, never passively,
  and never uploaded or saved to disk. Text is bounded; restricted API access
  degrades gracefully. No new permission requested.

Existing controlled fixtures now initialize their Planet allocator explicitly
because the real scheduler uses it for transient scratch. Historical archived
fixture hashes remain historical, not rewritten as new proof.

Exact terrain-upload retention and atmospheric basis caches remain experiments,
not part of this release. Native shutdown allocator warnings remain; this is
not a clean whole-engine leak check. No actual Android/laptop WebGL run was
available here. The next useful device evidence is More → Speed / fast-forward
→ Measure gameplay, with target, achieved pace, grid, timing and renderer text.
