# Exact finite-target validation hoist: promising modest WASM result, held

Production and live game are untouched. Candidate source is reproducibly generated by `prepare-wasm-edge-validation.py` into separate copied trees. No replacement liquid solver or root model is included.

## Codegen basis and change

Optimized LLVM for the actual production Planet wasm32 workload shows EdgeSource.rate already inlined. There is no remaining function-call overhead to remove. However, every directed edge retains three target f64 abs/bitcast/i64 finite checks and branches, even though targets originate in current f32 transformedPoints. The committed excerpt covers two consecutive edges; full12MiB LLVM remains local with hash.

Candidate performs one fresh finite-component pass over current transformedPoints every atmosphere tick. If all targets are finite, a separate edge-loop branch runs exactly the original widened-f64 subtraction, multiply, sum and divide operations, omitting only already-proven target checks. Source/wind validity, positive length, and finite accumulated length/dot checks remain. Any invalid target chooses the original generic loop for the entire tick. No topology cache, remembered validity flag, new arrays, extra persistent allocation, or save state is introduced. Bounds checking, OOM fallback and existing cache allocation are unchanged. Geometry changes are naturally revalidated on the next tick.

This is not the earlier large geometry/basis cache, target approximation, f32-rate replacement, or a different hydraulic law. It preserves operation order rather than accepting tolerances.
