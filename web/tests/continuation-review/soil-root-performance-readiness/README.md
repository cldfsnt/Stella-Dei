# Soil/root performance readiness: source audit and proposed gates

Read-only architecture audit; no new benchmark, ecology implementation, production change or device-speed conclusion. Reviewed stable v2 correctness kernel and design d1a94eb (`WATER-REPRESENTATION-PROPOSAL.md`). The proposed all-f64 physical path is NOT implemented. Its explicit exclusion of runtime f128 is appropriate; do not benchmark the old correctness-reference kernel as though it were the proposed shipping implementation.

## Actual cost/risk seams

- `soil_root_kernel_v2.step` validates and partitions all4 cohorts even for an empty physical patch. It performs f128 partition/flow/receipt arithmetic and invokes bounded_water scatter/gather for physical/root/store phases. `bounded_water` includes f128 division/conversion and u128 proportional division. This is source-level operation identification, not generated instruction counts or a measured slowdown. Compiler lowering/optimization must be inspected on the final WASM binary before attributing cost.
- Physical infiltration/evaporation/drainage must continue without organisms. Production `simulateMicrobes` skips biomass0/detritus0 cells, so inserting the whole kernel there misses empty-soil physics; executing all cohort machinery for every patch instead could impose full-mesh overhead. Candidate architecture should separate a bounded abiotic pass from occupied-cohort work, but zero/empty fast paths need material-equivalence tests, not speculative skipping of rain/recharge.
- Actual order is temperature jobs/join/swap; liquid/wind jobs/join; current liquid/vapor swap; atmosphere phase/advection; biology. Soil must read current post-hydrology water, never stale newWaterMass. dt>=15000 currently skips hydrology; new soil time behavior must be explicit, tested at boundary, and not silently coupled to a suspended physical subsystem.
- `newWaterMass` also holds atmospheric transport coefficients. Widening arrays is not merely adding precision: coefficient32 and donor-bound logic need an explicit new-model implementation. Do not round f64 authority back to f32 at each phase. Disabled legacy path must remain exact.
- `Planet.upload` streams waterMass as4bytes per vertex into an f32 GPU buffer. New f64 authority needs a read-only f32 render view with separately measured conversion/upload cost; passing f64 pointer to that upload corrupts the layout. Conversion cannot overwrite authority. Temperature/heat-capacity, tool edits, save capture/apply and zero-life water processes all consume physical water too.
- Existing SIMD water routines are f32-vectorized. New f64 arithmetic may alter lanes, memory traffic and compiler vectorization. Neither modest array sizes nor native scalar microbenchmarks predict browser cost. Trace actual emitted WASM calls (wide software arithmetic/division helpers), module size, heap growth and hot-loop operations rather than assuming optimizer behavior.

## Minimal staged actual-engine protocol (before launch, freeze source and law)

1. **Correctness gate first.** Freeze production release and candidate checksums, compiler/flags, saved inputs, world/model laws and requested timesteps. Disabled candidate must match every old physical/biological field and RNG after identical ticks and after uninterrupted-versus-restored continuation. Normalize only documented schema/default-zero additions. Enabled soil intentionally changes physics: compare its coupled receipts to the declared offline oracle/error envelope, not claim old-model bit parity. Fix error budget before outcomes; no topups or relaxed tolerance to improve biology.
2. **Workloads.** Use actual saved empty40k, early sparse40k and established natural60 40k worlds. Enabled empty case must include zero-soil startup AND legitimately wetted/evaporating substrate after ordinary finite water input, so an empty-fast-path cannot hide all soil cost. Established zero-root and supported-root cases separate abiotic from per-cohort cost; any prescribed root assignment is explicitly a performance stress fixture, not natural evolution. Include existing163842-resolution saved input and a clearly labeled fully occupied4-slot stress fixture if planning support at that size; do not describe synthetic dense biomass as earned ecology. Same frozen input per paired implementation, independent owned save parses, restore after each arm.
3. **Scheduler cost.** One cooperative partition to match current WASM scheduling, fixed1440s ticks with actual day/night,30untimed warmup+300measured coupled ticks. At least3 alternating pairs; report each pair, median and variability, allocation count/bytes, physical/biology stage times and material receipts. Logging/JSON/oracles outside timing. No extra per-frame full-world validation in measured candidate. Do not equate the requested timestep throughput with achieved user pace.
4. **Whole-frame cost.** Current-source actual update/render/gl.finish/swap at390×700 and laptop1366×768; paused,6h and24h requested pace, same camera/mode and display policy. At least3 runs with bounded warmup/measured frames; report p50/p95 and actual completed ticks, not just mean kernel cost. Include render-view conversion/upload stage. Native llvmpipe results are software-proxy only; no laptop/Android/GPU claim. Preserve input/save and disabled screenshots; enabled water appearance may legitimately differ and must match its actual physical state.
5. **WASM gate.** Compile the same candidate through pinned ReleaseSafe wasm32/Emscripten pipeline, record lowering/module imports, heap peak and actual scheduler CPU timings on frozen inputs. Node-hosted WASM is useful for engine arithmetic cost but not browser rendering/input/rAF. Only a real browser/device run can establish responsiveness/FPS; do not invent WebGL performance from a stubbed host. Keep final artifact/source provenance.
6. **Interpretation.** Any slowdown larger than paired variability warrants stage attribution before promotion; preregister acceptable budget with coordinator rather than pick a favorable percentage afterward. Require finite/nonnegative pools, governed receipts, disabled exactness and safe saves regardless of timing. No production enablement from a toy transfer benchmark or positive seven-day laboratory survival result.

## Recommended next step

Do not spend another full-world run on runtime-f128 v2 merely to discover it is costly. First finish the proposed consistent f64 local receipt/error contract and offline boundary tests, then freeze an actual enabled scheduler seam including abiotic empty patches. In parallel, regenerate current-release native full-frame baselines from unchanged saved worlds using existing harnesses, with clean CPU coordination. That provides useful reference data without pretending the not-yet-implemented soil model is ready. No soil parameters or optimization were selected in this audit.
