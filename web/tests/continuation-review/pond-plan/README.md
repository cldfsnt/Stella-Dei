# Bounded basin preview/apply foundation

Additive candidate only. Existing public makePond/makeNursery routing and shapeBasin implementation remain unchanged. No UI, new export, save schema or production action behavior changes. `old-pond-action.zig.txt` freezes the pre-change module for independent inspection.

`preview(planet, expected, selected, nursery, world) ?Plan` is allocation-free and non-mutating. It preserves old arithmetic/order, produces ordered IDs, floor count, exact represented elevation/water outputs and separate water added/removed totals (native water-mass units). It stores owner address, world serial, selected target, conversion bits, adjacency order, and bit-exact terrain/water for every footprint and outside-neighbor read. Fixed capacities are 19 output cells and 133 unique dependencies, with real mesh degree at most six. Oversized malformed graphs refuse rather than allocate.

`applyChecked(planet, &plan, selected, world) i32` rebuilds and compares the entire plan before any write. Changed outside values are rejected even if the same max surface would still win. Only elevation/water are written. The trusted native session must derive world serial from its actual state, keep the plan privately, and provide one-use confirmation tokens; the helper is not itself a security boundary or one-use ticket. Idempotent unchanged plans may remain applicable. It does not capture living populations yet: a future warning about occupied floor/rim cells must also bind those current populations/IDs or re-preview when they change. No claim that biology snapshots are protected by this terrain-only plan.

Five ReleaseSafe tests pass. They include 400 finite pond/nursery comparisons against the still-unchanged original action, both six-neighbor and pentagonal fixtures, exact full fixture equality (including biology sentinels), non-mutating preview, added/removed water accounting, stale world/selection/owner/outside input/topology/conversion and altered-plan refusals. Invalid/NaN/infinite/negative and extreme scale cases match the old action's success/refusal. Tiny conversion may legitimately refuse when representability prevents a valid rim; no relaxed precision rule is added.

Command: Zig0.13 `zig test src/pond_action.zig -O ReleaseSafe` (dedicated cache directories in recorded run). No heavy benchmark, browser acceptance, production world replay or performance claim. The next gate should compare this plan on the actual saved-world footprint before integrating any checked browser confirmation.
