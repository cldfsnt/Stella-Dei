# Inherited Sandbox defense: renderer/save integration review

Read-only production review after v67; no implementation, new biological law, rate selection or migration is authorized by this document. Candidate owner: grazing_traits, generator `web/tests/sandbox-toughness-prepare.py`; isolated `sandbox-toughness/{baseline,candidate}/src`. Its field is `Plant.toughness:f32=0` in[0,1], a handling-resistance surrogate, not a species or literal botanical anatomy. Mutation is disabled; prescribed experimental positive phenotypes are not natural evolution from zero.

## Existing seams

* `simulation/ecology.zig`: Plant contains optimum/generation only. `offspring` creates its own seeded PRNG and draws the thermal mutation once. Candidate copies toughness without an additional draw. Existing production/colonization functions can retain exact zero-trait branches.
* Candidate pays positive gross production by(1-d), donor propagule addition by(1-parent.d), and lowers rabbit maximum intake by1/(1+2d), including fragment intake. All cover remains edible and existing loss rates remain. These are proposed mechanisms under test, not verified general benefits. A visual must reflect that same authoritative field, never invent protection when biology has none.
* `Play.renderSprouts`: Sandbox uses actual vegetation>=.08 and nonflooded terrain, thermal optimum for lineage color, and identical branching vector silhouette for all patches. Existing pass is allocation-free, at most64 glyphs, close-view512 candidates. Low-cover populations may be real yet below the glyph threshold; do not promise every genotype is visibly rendered. Origin morphology/feeding markers are separate.
* Existing Sandbox details show actual cover, generation and optimum. This is the suitable place for a numeric toughness readout/cost explanation, not a new panel or unsupported species taxonomy.
* `Save.plants` aliases `Ecology.Plant`; capture returns the complete plantTraits array and apply memcpy-restores it. Adding a default field would therefore propagate automatically through JSON and snapshots, BUT current validation checks only optimum. That is not sufficient migration/validation.

2. Add explicit saved-law/version and finite toughness range validation before exposing persistent nonzero plants. Preserve missing legacy field as0, reject nonzero disguised legacy state, unknown law,NaN/Inf/out-of-range values before mutating the world. Current schema VERSION6 and Origin model_revision=version−1 are coupled: a Sandbox schema addition must explicitly preserve existing Origin semantics rather than blindly relabeling its biology. Choose a new production format/model contract only after audit; experimental version numbers are not an automatic migration path. Old files remain untouched on Load; only explicit Save writes the new format. Older binaries may reject the new save, so keep the user's original backup and explain rollback limitation.

Positive toughness can use broader/thicker, angular leaf contours inside today's footprint, retaining optimum color. Reuse the same stem+three leaf paths/fill/stroke count; use fixed coordinates or a few linear interpolations. No extra marker ring, trigonometry, animation, particles, texture allocation or per-world scan. Shape means "higher handling resistance" only, not a cactus/poison/thorn species. This is an illustrative visual encoding, not an anatomical claim. Keep Origin renderer and footprint/picking unchanged.
4. Existing selected-plant details can display numerical toughness and plain cost: slower growth/spread and slower rabbit feeding, not invulnerability. A concise help legend defines the silhouette. ## Important lifecycle decisions, not silent defaults

* Production PlaceVegetation only raises cover; it does not reset plantTraits. At exactly zero cover an old optimum/generation remains. If toughness is added, repainting an extinct patch would also revive the old defense. Decide whether this is a deliberate manual resurrection or whether a new empty-patch planting should use an explicit default genotype. Do NOT silently change the established zero-trait brush semantics. Test partial-cover augmentation separately from empty planting; do not call it natural offspring.
* Death/flood/fire reduction of cover must not create a hidden edible reserve, refill or protected floor. A residual genotype in an empty patch is not a living seedbank. The renderer must require current cover and must not draw defended life from stale traits alone.
* Colonization overwrites recipient traits with actual parent's copied toughness. It reads snapshotted cover but current plantTraits (in-place ordered trait writes); preserve existing ordering and document this when comparing zero-trait parity. Do not bundle a scheduler rewrite.
* `beginOrigin` requires no Sandbox cover/rabbits but may retain inactive plant-trait arrays. Do not activate Sandbox defenses in Origin or erase legitimate saved inactive fields without an explicit contract. Load must replace the entire trait array, not leak prior-world toughness.
* A single added f32 is expected to grow Plant8→12bytes:163,848bytes (~160KiB) at40,962 patches. Verify actual sizeof on native/WASM. Sandbox saves currently store every patch, including empty ones, so JSON overhead is dense; measure actual largest accepted saves. Existing bounded128MiB atomic writer must continue retaining canonical saves on overflow.

## Acceptance sequence

* Biology: d0 exact full original state/RNG; parent-copy identity/thermal draw unchanged; lower positive production/spread, slower funded bites, no extra satiety or inaccessible refuge; same actual habitat with/without grazing, all negative outcomes preserved. Prescribed d>0 does not establish spontaneous adaptation.
* Saves: legacy defaults, captured nonzero trait and exact restart continuation; invalid/disguised unknown law refusal atomic; load nonzero→legacy clears only by restored defaults, not stale memory; save-size boundary refusal preserves canonical file. Native and actual wasm32 target gates.
* Rendering: actual mixed-trait saved worlds plus labeled controlled d0/.25/.5/1 visual fixture; d0 pixel equality, clear positive differences at smallest visible glyph and selected portrait view, same cover/optimum for visual comparison. Rendering exact world/RNG/save purity, <=64 glyphs, same screen bounds/occlusion, no empty/dead glyph, Origin visuals unchanged.
* Mobile cost: count submitted paths and allocations; compare matched full-frame before/after only if changed geometry meaningfully increases work. No isolated draw microtest presented as device speed. Existing failed expensive history-marker experiments are a reason to replace contours rather than append decorative passes.

No source changes, heavy tests or publication performed by this review. The candidate's ongoing ecological outcomes remain the owner's separate evidence.

## Selection is not established by a local cost assay

Current occupied-patch replacement requires a neighboring thermal fitness advantage >0.1 while recipient cover<.35; same-optimum toughness variants cannot directly replace one another through that condition. They can spread into effectively empty cover<.0001, or coexist spatially and leave different vacancies under actual grazing. Therefore a local prescribed-trait growth/feeding assay does not demonstrate selection or an accessible zero→positive adaptation path. Before promotion as an evolutionary feature, preregister a spatial mosaic with equal thermal optima, paid equal initial cover, deliberate vacancies and actual rabbit pressure; include ungrazed controls and swapped spatial assignments. Let current growth, depletion, movement and recolonization determine outcomes. Report occupied shares/cover and extinction/recolonization honestly. Do not add a synthetic defense-fitness replacement score to force a winner, and do not reinterpret a manually assigned defended patch as a naturally mutated lineage. Mutation/progression requires a separately tested inherited law after physical tradeoffs are established.
